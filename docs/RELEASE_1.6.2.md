# Marchland Oaths 1.6.2 — the confirmation had a side door

This patch changes how the game treats a save from before authenticated profiles, and it finishes the 1.6.2 release itself: the patch notes, the acceptance evidence and the version metadata for this edition were missing from the repository at HEAD `f7a3155`, so this edition now ships them. It does not touch gameplay, balance or art, except for removing two empty autoload scripts that nothing used. Audio gets two small fixes: the purchase cue is no longer the same sound as the pickup cue, and the default music volume is raised so the soundtrack is actually audible.

## What changed

A v1–v3 save carries no HMAC because those formats predate save signing; it is verified by its published checksum. In 1.6.1 such a file was no longer applied silently: the loader refused it, remembered it as pending, and the game asked once, in the active language, whether to import it into that slot. Two reviews of that fix found two ways the old file could still slip in.

**A declined file could return through the slot backup.** `_store` read the previous body again when writing an ordinary save, without the confirmation check, so a declined checksum-only body could be promoted into the slot's authenticated backup and re-signed on the next write. `_store` now trusts a previous body only from the exact file the player just confirmed; otherwise the write proceeds with no backup candidate, and the untouched original is preserved as `.rejected` (one copy per rejection, so a later decline cannot destroy the bytes an earlier one preserved). `tests/test_legacy_import.gd` asserts the declined-then-saved sequence.

**The answer belonged to a pathname, not to the bytes it was about.** The pending set was keyed globally, so a legacy save swapped in while the dialog was open was imported and re-signed under the earlier click, and a load of one slot could offer another slot's refused body. Consent is now bound to a SHA-256 digest of the exact file text: `SaveSystem` records `legacy_pending[path] = digest`, `confirm_legacy_import` authorises only that digest, and if the bytes behind the slot changed while the question was open, nothing is applied, the current body stays pending for a fresh question, and the player is told the file changed (`msg.legacy_changed`). Prompts are per slot: a second slot asking a question gets its own dialog instead of silently reusing the first one.

**Release packaging.** The 1.6.1 archive shipped documents that pointed at an evidence folder left behind, and the only guard against a repeat sat in untracked build tooling, so a checkout could neither see the packaging list nor verify it. The document inventory, the licence relocations and the reference contract now live in `tools/release_packaging.py`, and `tests/test_release_packaging.py` asserts the list is complete, carries the current edition's evidence, holds no private material, resolves every reference a shipped document makes — and still fires when a referenced document is removed, so the check cannot pass by being empty. Resolving every reference against the filesystem made the contract take minutes; one walk of `docs/` replaces the per-token stat and resolve calls.

**Release completion in this commit.** The 1.6.2 patch notes (`docs/RELEASE_1.6.2.md`), the 1.6.2 acceptance evidence (`docs/acceptance-1.6.2/`) and the 1.6.2 certificate and report did not exist in the repository, while `README.md`, `docs/HANDOFF.md` and `tools/release_packaging.py` already referenced them. They are added here, and the stale version metadata is corrected: `export_presets.cfg` carried `1.6.0.0` in both Windows presets (now `1.6.2.0`), `README.md` was still titled 1.6.0, `QUICK_START.md` still described 1.5.1, and `assets/CREDITS.md` was still titled 1.5.0. Two empty autoload scripts, `scripts/autoload/WorldManager.gd` and `scripts/autoload/InputManager.gd` (`extends Node` + `func _ready(): pass`, referenced by nothing in `scripts/`, `scenes/` or `tests/`), are removed from `project.godot` and deleted; the autoload count goes from 25 to 23. The 1.6.1 notes said 810 catalog keys; the catalogs actually hold 811 unique keys in each locale (813 CSV rows: header, 811 keys, one empty row), with identical key sets and no missing translation — the count is corrected here, not the data.

**Audio: purchase finally sounds like a purchase.** A byte-level check of all 42 shipped WAVs found exactly one duplicate pair: `assets/audio/purchase.wav` and `assets/audio/pickup.wav` were the same file (SHA-256 `de4aa8…`), because the generator gave both names the same two bell notes (79, 84). `tools/generate_audio.py` now gives every bell cue its own arpeggio — purchase is [76, 81, 84], pickup stays [79, 84] — and `purchase.wav` was regenerated with the project's own generator, so the provenance hashes in `assets/audio/interface-provenance.json` are updated by the same run and `tests/test_audio_assets.py` / `tests/test_soundtrack.py` still pass. The music itself was measured, not guessed: the four Lyria tracks are 32 kHz stereo, RMS ≈ 2130 (≈0.065 of full scale, peak 0.28–0.43), so at the old default music volume of 0.30 the soundtrack sat barely above inaudible. `scripts/autoload/SettingsManager.gd` raises the default to 0.65; existing player settings are untouched.

## Compatibility

Profiles published by 1.4.0 and 1.5.0 already carry the HMAC and load exactly as before, with safe defaults for the oath fields and a backup before the one-way migration. Only genuinely old v1–v3 files now need a single confirmation, and that confirmation is bound to the exact bytes shown. Nothing is deleted, and no save format changed: schema 4, the five manual slots, autosave and iron rules are untouched.

## Verification

The exchange is asserted end to end in `tests/test_legacy_import.gd` for both locales: a silent load is refused, the pending entry names exactly that file, the dialog carries the localized title, body and both actions, confirming restores the real 1.1 state and re-signs it under schema 4, declining leaves the file untouched, a declined-then-saved sequence preserves the original as `.rejected` instead of promoting it, and a file swapped while the dialog is open is not imported under the earlier answer. `tests/test_legacy_migration.gd` and `tests/test_oath_migration.gd` exercise the same two-step path against the shipped 1.1 fixtures. The source gate for this completion was run in Godot 4.7 Stable (`4.7.stable.official.5b4e0cb0f`) on Linux, in the CI order (`test_checkout_bytes.py`, editor import, `tools/check_gdscript_warnings.py` with 49 warning categories as errors): after the editor import, 104 of 105 shipping scripts compile clean and the single failure is `scripts/ui/TitleBackdrop.gd` preloading `res://assets/art/title_painting.png`, a file present in the repository (blob `26d98f5…`) but absent from the sparse checkout used for the run — a checkout artefact, not a code defect, with a full-checkout re-run expected at 105/105. The Python contracts run here: PASS for copy contract (811 keys per locale), promise matrix (3278 original entries) and repository isolation (7 tests); the remaining six (checkout bytes, critical manifest, mechanics matrix, licence bytes, soundtrack, audio assets) failed only on files absent from the same sparse checkout, each verified present in HEAD by blob, so they are not established as defects and need a full-checkout re-run. See `docs/acceptance-1.6.2/` for the evidence recorded for this edition. The rendered full-campaign gate (83 cases per locale, soak, native exported-build routes) was **not** re-run in this completion: the last executed rendered gate is the 1.6.1 one recorded in `docs/acceptance-1.6.1/`, and the 1.6.2 code changes touch only the save path (`SaveSystem._store`, `_read_previous`, `_preserve_rejected`, digest-bound confirmation) and the packaging tooling — no rendering, asset, scene, balance or save-format code. Re-running the rendered gate and the encrypted export remains an open step before the published ZIP; see `docs/FINAL_REPORT.md` and `docs/HANDOFF.md`.

## Honest limits

Windows x64 only, offline, Compatibility/OpenGL rendering, and the executable is not Authenticode signed. This change removes two silent state-injection paths; it does not make the offline protection unbreakable — a device owner can still read the installation key or patch the binary. Automated checks are finite and are not a human playtest. The encrypted Windows export additionally requires the private matching template and script-encryption key, which live outside the repository; the source tree in this commit is export-ready, but the published ZIP and its sums can only be produced from the build environment that holds them. Owner checks in [HANDOFF](HANDOFF.md) remain outstanding before announcement.

## Русский

Патч меняет только обращение со старыми сейвами и доводит до конца сам релиз 1.6.2. Файл схемы v1–v3 не содержит HMAC и проверяется контрольной суммой. В 1.6.1 такой файл уже не применялся молча: загрузчик отказывал, запоминал его как ожидающий решения, а игра один раз спрашивала на активном языке, импортировать ли его в этот слот. Две проверки этого исправления нашли два пути, которыми старый файл всё равно мог просочиться.

**Отклонённый файл мог вернуться через резервную копию слота.** При обычной записи `_store` снова читал предыдущее тело без проверки подтверждения, и отклонённое тело могло попасть в аутентифицированную резервную копию и переподписаться при следующей записи. Теперь `_store` доверяет предыдущему телу только из файла, который игрок только что подтвердил; иначе запись идёт без кандидата в резервную копию, а нетронутый оригинал сохраняется как `.rejected` — по одной копии на каждый отказ, чтобы позднейший отказ не уничтожил байты, сохранённые ранним.

**Ответ принадлежал пути, а не байтам, о которых спрашивали.** Ожидающие записи были общими, поэтому легаси-сейв, подменённый, пока диалог открыт, импортировался и переподписывался по более раннему клику, а загрузка одного слота могла предложить отклонённое тело другого слота. Теперь согласие привязано к SHA-256-дайджесту точного текста файла: `SaveSystem` запоминает `legacy_pending[path] = digest`, `confirm_legacy_import` разрешает только этот дайджест, а если байты за слотом изменились, пока шёл вопрос, ничего не применяется, текущее тело остаётся ожидающим нового вопроса, а игрок получает уведомление, что файл изменился (`msg.legacy_changed`). Вопросы — по слотам: второй слот получает свой диалог, а не переиспользует первый молча.

**Упаковка релиза.** Архив 1.6.1 поставлял документы, ссылавшиеся на папку доказательств, которую не положили в скачивание, а единственная защита от повтора жила в неотслеживаемом сборочном инструменте. Теперь перечень документов, перемещения лицензий и контракт ссылок живут в `tools/release_packaging.py`, а `tests/test_release_packaging.py` проверяет полноту списка, наличие доказательств текущей версии, отсутствие приватных материалов и разрешение каждой ссылки — и по-прежнему срабатывает, если убрать документ, на который ссылаются, так что проверка не может пройти, будучи пустой.

**Доведение релиза в этом коммите.** Заметки к патчу 1.6.2, доказательства приёмки 1.6.2, сертификат и отчёт для 1.6.2 в репозитории отсутствовали, хотя README, HANDOFF и упаковочный инструмент на них уже ссылались. Они добавлены здесь, а устаревшие метаданные исправлены: в `export_presets.cfg` в обоих пресетах Windows стояла версия `1.6.0.0` (теперь `1.6.2.0`), `README.md` был озаглавлен 1.6.0, `QUICK_START.md` описывал 1.5.1, а `assets/CREDITS.md` — 1.5.0. Два пустых автозагружаемых скрипта, `WorldManager.gd` и `InputManager.gd` (`extends Node` и пустой `_ready`, нигде не используемые), удалены из `project.godot` и из репозитория; автозагрузок стало 23 вместо 25. В заметках 1.6.1 было сказано про 810 ключей каталога; на самом деле в каждой локали 811 уникальных ключей (813 строк CSV: заголовок, 811 ключей, одна пустая строка), наборы ключей совпадают, пропущенных переводов нет — исправлен подсчёт, а не данные.

**Звук: покупка наконец звучит как покупка.** Проверка всех 42 WAV по байтам нашла ровно одну пару-дубликат: `purchase.wav` и `pickup.wav` были одним файлом (SHA-256 `de4aa8…`), потому что генератор давал обоим именам одни и те же две ноты колокола (79, 84). Теперь у каждого сигнала своё арпеджио — покупка [76, 81, 84], подбор остаётся [79, 84], — а `purchase.wav` перегенерирован штатным генератором проекта, поэтому хеши происхождения в `interface-provenance.json` обновлены тем же запуском, и тесты аудио по-прежнему проходят. Музыку тоже померили, а не угадывали: четыре трека Lyria — 32 кГц, стерео, RMS ≈ 2130 (≈0,065 от полной шкалы, пик 0,28–0,43), так что при старой громкости музыки по умолчанию 0,30 саундтрек был едва слышен. `SettingsManager.gd` поднимает значение по умолчанию до 0,65; настройки существующих игроков не трогаются.

Совместимость: профили 1.4.0 и 1.5.0 загружаются как раньше, они уже подписаны. Схема сейвов, пять слотов, автосохранение и железный режим не меняются; ничего не удаляется. Ограничения те же: только Windows x64, офлайн, без подписи, автотесты не заменяют ручной прогон. Зашифрованный экспорт требует приватный шаблон и ключ шифрования скриптов, которые живут вне репозитория; исходники в этом коммите готовы к экспорту, но опубликованный ZIP и его суммы можно собрать только в сборочном окружении, где есть ключ. Проверки владельца из [HANDOFF](HANDOFF.md) остаются открытыми до объявления.
